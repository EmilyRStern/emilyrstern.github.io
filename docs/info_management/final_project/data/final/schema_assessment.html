Schema Assessment — proposed 6-table ER vs. NSF-filtered data

Verdict: the 6-table shape (agencies, opportunities, change_log, recipients, awards, terminations) is the right backbone for the research question and the data we have. It loads cleanly. There are five tweaks I’d make before standing it up, plus one scope mismatch worth resolving.

What’s confirmed by the data

Schema entity Source after NSF filter Row count Natural key works?
agencies derived from awarding_agency_name in awards / opportunities ~1 (just NSF) for now yes, agency_code is unique
opportunities grants_gov_nsf.csv 1,330 yes — OpportunityID is unique per opp
change_log (empty until you take a 2nd Grants.gov snapshot) 0 yes — surrogate change_id
recipients distinct from usaspending_nsf.parquet 2,856 unique UEIs yes — recipient_uei
awards aggregated from usaspending_nsf.parquet 37,535 unique awards (from 57,812 transactions — 1.54 transactions/award) yes — assistance_award_unique_key
terminations nsf_terminations.csv 1,996 yes — grant_id

Recommended tweaks (ordered by importance)

1. Resolve the research-question scope mismatch — do this first

The diagram’s research question reads “…either rescinded at the opportunity level… or terminated at the award level (per the five agency feeds)…”. We just dropped the EPA/CDC/NIH/SAMHSA terminations files when filtering to NSF. Two options:

  • Option A — narrow the question to NSF. Rewrite to “…how much NSF funding has been disrupted…” and keep the 6-table schema as-is. Recommended for a 6-table assignment.
  • Option B — keep the five-agency scope. Re-run the filter to also copy through epa_terminations.csv, cdc_terminations.csv, nih_v3_terminations.csv, samhsa_terminations.csv, and add source_agency_id to populate from filename. The schema already supports this via terminations.source_agency_id — no schema change needed, just data pipeline change.

2. Add is_active columns the schema already implies

We just added is_active to all four output files but the diagram doesn’t show it. Add to:

  • opportunities.is_active (TRUE while record_type LIKE '%synopsis%' OR LIKE '%forecast%')
  • awards.is_active (TRUE while period_of_performance_current_end_date >= today)
  • terminations.is_active (TRUE if NOT terminated, or reinstated)

3. The awards table needs a few more columns to be useful

Proposed columns: award_unique_key, award_id_fain, recipient_uei, awarding_agency_id, cfda_number, total_obligated_amount. Add at minimum:

  • period_of_performance_start_date, period_of_performance_current_end_date — drives is_active and “period of disruption” calcs
  • awarding_sub_agency_name — for NSF this is the directorate (BIO, CISE, ENG, GEO, MPS, SBE, EHR/EDU, OISE, OPP, OIA, TIP) and is essential for grouping
  • total_outlayed_amount_for_overall_award — distinct from obligation; you’ll want both for the disruption-dollar metric
  • action_date (most-recent transaction date) — useful for “freshness” of the award snapshot

Important loader note: the parquet has 57,812 transaction rows but only 37,535 distinct awards. Aggregate to one row per assistance_award_unique_key when loading — sum federal_action_obligation, max period_of_performance_current_end_date, etc. Don’t pipe transactions in directly.

4. The terminations table is too thin for the research question

Proposed columns: termination_id, source_agency_id, award_id_fain, current_status, latest_termination_date, award_value.

The dollar-disruption answer lives in fields the schema currently drops. Add:

  • reinstated, reinstatement_date — without these, “active” terminations vs. reversals collapse into one number
  • post_termination_deobligation — the actual dollar figure that was pulled back; this is the headline metric of your research question
  • nsf_total_budget, usasp_total_obligated, estimated_remaining — funding context
  • nsf_program_name, directorate, division — NSF program structure for grouping
  • project_title — for human-readable reporting

Also: the join key from terminations to awards is award_id_fain, but in nsf_terminations.csv the column is grant_id (the NSF award number, e.g. 2201796). USAspending’s award_id_fain for the same award is also just 2201796. So the join works directly — but document this: terminations.award_id_fain should be populated from nsf_terminations.grant_id.

5. The opportunities table needs three additions

Proposed columns: opportunity_id, agency_id, title, cfda_number, post_date, estimated_total_funding. Add:

  • opportunity_number — human-readable opp ID (e.g. NSF-25-501); distinct from internal PK
  • close_date, archive_date — drives is_active
  • cfda_numbers (plural) — opportunities can list multiple CFDAs (the source field is CFDANumbers, comma-separated). Either keep as a delimited string or break out to a opportunity_cfda junction table. The 6-table cap argues for keeping the delimited string.

Things that look right and don’t need changing

  • change_log weak/audit-entity styling is correct — it depends on opportunities and is appended to over time as you take new Grants.gov snapshots.
  • recipients self-reference (parent_uei) is real in the source data and worth keeping (universities have parent UEIs for system offices).
  • agencies self-reference (parent_agency_id) is unused with NSF-only data, but harmless to keep for future expansion.
  • award_id_fain as a unique key (UK) on awards is correct — USAspending guarantees one FAIN per assistance award.

Suggested final schema (deltas only)

opportunities
  + opportunity_number     VARCHAR   -- human-readable opp id
  + close_date             DATE
  + archive_date           DATE
  + cfda_numbers           VARCHAR   -- comma-separated; supersedes single cfda_number
  + is_active              BOOLEAN

awards
  + period_of_perf_start          DATE
  + period_of_perf_end            DATE
  + awarding_sub_agency_name      VARCHAR
  + total_outlayed_amount         DOUBLE
  + action_date                   DATE
  + is_active                     BOOLEAN

terminations
  + reinstated                    BOOLEAN
  + reinstatement_date            DATE
  + post_termination_deobligation DOUBLE   -- THE headline metric
  + nsf_total_budget              DOUBLE
  + estimated_remaining           DOUBLE
  + project_title                 VARCHAR
  + nsf_program_name              VARCHAR
  + directorate                   VARCHAR
  + is_active                     BOOLEAN

agencies, recipients, and change_log need no changes.

Recommendation

Pick Option A (narrow research question to NSF), apply the five field-list tweaks above, and we’re ready to load. If you want to stay multi-agency, say the word and I’ll re-run the filter to bring back the four other agency termination files.

Decision (2026-04-30)

Going with Option A. Research question narrowed to NSF; all five tweaks applied. The implementing artifacts are:

  • er_diagram.html — updated to reflect NSF-only scope and the new field list
  • scripts/11_setup_nsf_db.R — DDL for the revised schema, builds data/final/nsf_volatility.duckdb
